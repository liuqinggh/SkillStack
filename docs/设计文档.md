# demo-csbot 设计文档

## 一、项目概述

**demo-csbot** 是一个基于 **Deep Agent**（LangGraph + deepagents）的客服/聊天机器人 Demo，对外仅暴露 **Runtime 形态** 的 HTTP API（`/api/runtime/...`）；入参校验（如 **`validate_run_message`**）与 Run 编排由 **`RuntimeService`** 与路由层完成；LangGraph 状态由 checkpointer 按线程维度维护。

### 1.1 技术栈

| 层级 | 技术 |
|------|------|
| Web 框架 | FastAPI + Uvicorn |
| Agent 框架 | deepagents（含 create_deep_agent、Skills、FilesystemBackend） |
| 图与状态 | LangGraph（MemorySaver checkpointer） |
| LLM 接入 | langchain-openai（OpenAI 兼容，可接 LiteLLM） |
| 配置 | YAML（conf.yaml / conf.example.yaml） |
| 会话摘要 | 内存 **SessionsService**（`session_id` / `latest_run_id`） |

### 1.2 目标与约束

- **多轮对话（HTTP）**：客户端先 `POST /api/runtime/sessions` 获得 `session_id`，再对同一 `session_id` 多次 `POST /api/runtime/runs`；后端将 LangGraph 的 `thread_id` 与 session/run 关联，由 checkpointer 维护状态，每次请求只带当前一条 `input.message`。
- **非流式与 SSE**：`POST /api/runtime/runs` 中 `stream=false` 返回 **RunSummary**；`stream=true` 时返回 SSE，事件为规范化 **RuntimeEvent**（首包 `started`，随后 `delta`…，结束 `done` 或 `error`）。
- **可配置**：LLM、agent、sandbox、API、流式、日志等均通过 `conf.yaml` 驱动。

## 二、系统架构

### 2.1 分层结构

```
┌─────────────────────────────────────────────────────────────────┐
│  入口层                                                           │
│  app.py (FastAPI)                                                 │
└───────────────────────────────┬─────────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────────┐
│  API 层 (api/)                                                    │
│  routes: /, /health, /api/runtime/sessions, /api/runtime/runs    │
│  deps: AppContext 构建与注入   error_handlers: 统一异常响应        │
└───────────────────────────────┬─────────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────────┐
│  Runtime / 服务层                                                 │
│  RuntimeService: 单次 HTTP run → RuntimeEvent 流（校验 message）  │
│  SessionsService: 内存 session 与 latest_run_id（HTTP 会话摘要）    │
└───────────────────────────────┬─────────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────────┐
│  适配器层 (adapters/)                                             │
│  DeepAgentAdapter: 封装 create_deep_agent，run_turn / run_stream   │
│  LocalSandboxBackend (sandbox_adapter): 本地 shell 执行 sandbox    │
└───────────────────────────────┬─────────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────────┐
│  领域与基础设施                                                   │
│  domain: models (ChatRequest/Response, StreamEvent…)             │
│          errors (DemoCsBotError, ConfigError, ValidationError…)   │
│  runtime: events（RuntimeEvent*）, lifecycle（validate_run_message） │
│  config: Settings 及各 subsection（App, Llm, Agent, Sandbox…）     │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 请求流（HTTP：Runtime Run，非流式）

1. 可选：`POST /api/runtime/sessions` 创建逻辑会话，得到 `session_id`。
2. 客户端 `POST /api/runtime/runs`，`stream: false`，body 为 **RunRequest**（见 `api/schemas/run.py`）。
3. **routes** 在事件循环中用 `run_in_executor` 收集 **RuntimeService.stream_run** 产生的全部 **RuntimeEvent**；若末尾为 **RuntimeEventDone** 则 `status=succeeded`，否则 `failed`。
4. 返回 **RunSummary**：`run_id`、`status`、`session_id`；若提供 `session_id` 则更新 **SessionsService** 的 `latest_run_id`。超时返回 504（`api.chat_timeout_sec`）。

### 2.3 请求流（HTTP：Runtime Run，SSE）

1. 客户端 `POST /api/runtime/runs`，`stream: true`。
2. 若 `stream.sse_enabled` 为 false 则 404；否则返回 **StreamingResponse**，媒体类型 `text/event-stream`，载荷为 **RuntimeEvent** 的 SSE 序列化（`started` → `delta` → … → `done` | `error`）。
3. **RuntimeService** 通过适配后的引擎 **iter_stream_deltas**（或兼容 **run_stream**）产出文本增量；入参校验统一走 **`validate_run_message`**（`api.max_request_chars`，见 `runtime/lifecycle.py`）。
4. 底层 **DeepAgentAdapter.run_stream** 行为与 token 粒度、退化策略等仍参见 [QA：流式为什么慢](./QA.md#q2-流式接口api-v1chatstream为什么慢)（问答文档标题仍沿用历史路径，语义适用于当前 Runtime SSE）。

## 三、模块说明

### 3.1 入口

- **app.py**：加载 `conf.yaml`，调用 `create_app(conf_path)` 得到 FastAPI app；`python app.py` 时用 uvicorn 启动，host/port/debug 来自 `app` 配置。

### 3.2 应用工厂与依赖（app_factory / deps）

- **create_app**：FastAPI 实例、CORS、router、全局异常处理；**AppContext** 通过 **get_context(conf_path)** 单例（lru_cache）获取。
- **build_context**：按 conf_path 加载 **Settings** → 内存 **SessionsService**、**DeepAgentAdapter**、**UploadsService**、**ThreadPoolExecutor**。常量 **`RUNTIME_SERVICE_ID`**（`"demo-csbot-runtime"`）与 **`/health`** 的 `service` 字段对齐。非流式 Run 在 route 中通过 `run_in_executor` 收集事件，避免阻塞事件循环。

### 3.3 API 路由（`api/routes/` 包）

| 路径 | 方法 | 说明 |
|------|------|------|
| `/` | GET | 返回 static/index.html |
| `/health` | GET | `{ "status": "ok", "service": "demo-csbot-runtime", "runtime": "ready", "version": "<app.version>" }`（`service` 来自 **`api/deps.RUNTIME_SERVICE_ID`**，`version` 来自 **`settings.app.version`**） |
| `/api/runtime/sessions` | POST | 创建会话，返回 `session_id` |
| `/api/runtime/sessions/{session_id}` | GET | 查询会话摘要（含 `latest_run_id`） |
| `/api/runtime/runs` | POST | 执行 Run：`stream=false` 返回 **RunSummary**；`stream=true` 返回 SSE（**RuntimeEvent**） |

**RunRequest** 字段见 `api/schemas/run.py`（`input`、`agent`、`model`、`session_id`、`stream`、`metadata`）。SSE 事件类型见 `runtime/events.py`（`error` 使用 `message` 字段）。

### 3.4 领域模型（domain/models.py 等）

- **ChatRequest / ChatResponse**：历史/文档用请求形状；当前公共 HTTP 不挂载旧版 chat 路由。
- **StreamEvent**：旧版流式 DTO，**已无对应 `stream_service` 模块**；领域模型仍保留于 `domain/models.py`，HTTP 流式以 **RuntimeEvent** 为准。
- **RunRequest / RunSummary**：HTTP Runtime 入参与非流式响应（`api/schemas/run.py`）。

### 3.5 领域异常（domain/errors.py）

- **DemoCsBotError**：基类。
- **ConfigError**：配置加载/校验错误。
- **ValidationError**：请求校验（如 message 为空、过长）。
- **EngineError**：LLM/agent 执行异常。
与 **error_handlers** 对应：ValidationError → 400，ConfigError → 500，其余 DemoCsBotError → 500。

### 3.6 配置（config/settings.py）

从 YAML 构建不可变 **Settings**，包含：

- **AppConfig**：name、version、host、port、debug。
- **LlmConfig**：provider、model、base_url、api_key、temperature、timeout_sec、max_tokens。
- **AgentConfig**：skill_manager_root、skills_sources、memory_files、thread_pool_workers、system_prompt。
- **SandboxConfig**：root_dir、virtual_mode、execute_timeout_sec、max_output_chars。
- **ApiConfig**：cors_allow_origins、max_request_chars、chat_timeout_sec。
- **StreamConfig**：sse_enabled、heartbeat_sec、chunk_strategy。
- **LoggingConfig**：level、format、file_path、rotate_policy。
- **project_root**、**conf_path**：由 conf 文件路径解析。

必填项缺失或类型/取值范围不符会抛出 **ConfigError**。

### 3.7 适配器

- **DeepAgentAdapter**：  
  - 使用 **Settings** 构造 **ChatOpenAI**（model、base_url、api_key、temperature、timeout、max_tokens）与 **create_deep_agent**（model、system_prompt、skills_sources、backend=LocalSandboxBackend、memory、checkpointer=MemorySaver()）。  
  - **run_turn**：stream_mode="values"，从最终 state 的 messages 中取最后一条 AIMessage 的 content（支持 str/list 等 content 结构）。  
  - **run_stream**：stream_mode="messages"，解析 AIMessageChunk 做 delta 累加与 yield；若无任何 delta 则回退为 run_turn 整段输出。

- **LocalSandboxBackend**（sandbox_adapter）：继承 deepagents 的 **FilesystemBackend** 与 **SandboxBackendProtocol**，在 **sandbox.root_dir** 下用 **subprocess.run(shell=True)** 执行命令，超时与输出截断由 **SandboxConfig** 控制。

### 3.8 前端

- **static/index.html**：静态单页，首次发送前 `POST /api/runtime/sessions`，随后 `POST /api/runtime/runs`（`stream: true`）读 SSE；根据 `started` 显示“思考中…”，根据 `delta`/`done` 更新正文（`error` 使用 `message`）。

## 四、配置说明

以 **conf.example.yaml** 为参考：

- **app**：服务名、版本、监听 host/port、是否 debug。
- **llm**：LiteLLM/OpenAI 兼容端点（base_url、api_key）、model、temperature、timeout_sec、max_tokens。
- **agent**：skill_manager_root、skills_sources、memory_files、thread_pool_workers、system_prompt。
- **sandbox**：root_dir（与 skill 同根或一致）、virtual_mode、execute_timeout_sec、max_output_chars。
- **api**：cors_allow_origins、max_request_chars、chat_timeout_sec（非流式 Run 等待上限，可选，默认 120）。
- **stream**：sse_enabled、heartbeat_sec、chunk_strategy。
- **logging**：level、format、file_path、rotate_policy。

生产环境复制为 `conf.yaml` 并修改路径、密钥等敏感项。

## 五、多轮对话与消息语义

- **会话标识命名约定**：业务层（API、存储、日志）统一使用 **`session_id`**；DeepAgent/LangGraph 内部仍使用 **`thread_id`** 作为框架配置键名，但其值等同于 `session_id`（仅名称不同）。
- **多轮（HTTP）**：**MemorySaver** 按内部 **thread_id**（值为 `session_id`）持久化图状态；`session_id` 用于关联多次 Run 与 `latest_run_id`，具体映射由 **runs** 路由实现（有 `session_id` 时优先使用其作为 session stream id，否则使用新生成的 `run_id`）。每次请求只传当前一条 **input.message**。
- **持久化格式**：`chat_sessions.jsonl` 采用“每个 `session_id` 一行、消息聚合在 `messages[]`”的结构；新写入仅输出 `session_id`，读取兼容历史 `thread_id` 字段。
- **“多条消息合并”**：若用户一次输入多段（多行），建议拼成一条 **message** / **input.message** 发送。扩展 **messages[]** 等仍参见 [QA：多条消息合并](./QA.md#q1-用户多条消息如何合并后给到后端)。

## 六、流式行为与优化

- **首字慢**：图在 LLM 前还有 skills 加载、规划等步骤；stream_mode="messages" 可能非逐 token；无 delta 时退化为整段 run_turn，导致“长时间无输出后一次性返回”。
- **已做**：流式响应先发 **started**，前端显示“思考中…”；收到 delta 或 done 后替换为正文。
- **可做**：简化图、确认上游是否按 token 流式、心跳、换模型/代理等。详见 [QA：流式接口为什么慢](./QA.md#q2-流式接口api-v1chatstream为什么慢)。
