# demo-csbot 开发日志

## 2026-05-03

### 主题：会话标识命名收敛（业务 `session_id` vs DeepAgent `thread_id`）

### 1) 约定统一

- **业务层统一使用 `session_id`**（API 字段、持久化字段、文档术语）。
- **DeepAgent/LangGraph 内部继续使用 `thread_id` 作为配置键名**（框架约定字段），但其传入值与业务 `session_id` 保持一致。

### 2) 数据与存储约定

- `data/chat_sessions.jsonl` 顶层主键统一为 `session_id`。
- 每条消息内部字段统一为 `session_id`。
- 存储格式按“**每个 session 一行**”维护，消息聚合在该行的 `messages` 数组中。
- 非 UUID 的历史 `thread_id` 在迁移时映射为稳定 UUID（uuid5），避免随机漂移。

### 3) 兼容策略

- 读取逻辑兼容历史字段 `thread_id`（仅用于旧数据兼容）。
- 新写入只输出 `session_id`，不再写 `thread_id`。

### 4) 边界说明

- 本项目对外语义以 `session_id` 为准；
- 若在 DeepAgent 相关实现中看到 `thread_id`，应理解为“框架内部键名”，不是业务命名回退。

### 5) 前端方案（assistant-ui + 现有 FastAPI Runtime）

- **目标**：用可组合的聊天 UI 基元承载流式对话，并直连本仓库已实现的 Runtime HTTP/SSE，不引入第二套对话协议。
- **主要依赖**（见 `frontend/package.json`）：
  - 框架：`@umijs/max`（Umi Max）
  - UI：`antd`、`@ant-design/icons`
  - 聊天：`@assistant-ui/react`、`@assistant-ui/styles`（样式入口：`@assistant-ui/styles/styles/index.css`）
  - 包管理：`package.json` 的 `packageManager` 指向 **pnpm**；本地安装建议优先 `pnpm install`。
- **页面入口**：`frontend/src/pages/index.tsx` 仅渲染 `CsBotAssistantPanel`，业务与对接逻辑集中在组件层。
- **核心实现**：`frontend/src/components/CsBotAssistantPanel.tsx` + `CsBotAssistantPanel.less`
  - **运行时**：`AssistantRuntimeProvider` + `useLocalRuntime`，通过 **`ChatModelAdapter`** 把模型调用映射到后端。
  - **线程 UI**：`ThreadPrimitive`（消息列表 + 自动滚动）、`MessagePrimitive`（用户/助手气泡）、`ComposerPrimitive`（输入与发送）。
  - **开场**：`BootstrapHi` 在挂载后自动 `append` 一条用户消息 `hi`，用模块级 `bootstrapHiSent` 规避 React StrictMode 双挂载导致的重复发送。
- **与 Runtime 的对接**（相对路径，由 Umi 代理到 FastAPI）：
  1. **会话**：`POST /api/runtime/sessions` 返回 `session_id`；在首次需要时创建（发消息流式前，或侧栏首次上传前 `ensureSessionForUpload`），`sessionId` 保存在 `ref` 并展示在侧栏。
  2. **对话流**：`POST /api/runtime/runs`，`Accept: text/event-stream`，请求体包含 `input.message`、`input.attachments`、`agent`、`model`、`session_id`、`stream: true` 等；响应体按 **SSE** 分块解析（`parseSSEEvents`），处理 `delta` / `done` / `error`，以 **累积文本** 形式 `yield` 给 adapter，驱动 assistant-ui 的流式更新。
  3. **上传**：`POST /api/runtime/uploads`，`multipart/form-data` 字段 `session_id`、`ocr_mode`、`file`（可多文件循环上传）；返回的 `attachment_id` 进入待发送列表，随下一条用户消息一并提交，发送成功后清空 pending。
- **单 Agent 与模型写死**（与当前 Phase 1 叙事一致）：
  - `agent.id` 固定为 `default`（常量 `DEPLOYMENT_AGENT_ID`），需与后端 `agent.default_profile_id` 一致。
  - `model` 当前为 `{ provider: 'litellm', model: 'gemini-2.5-flash' }`（可按产品需求改为读配置或环境变量）。
- **侧栏能力**：OCR 模式下拉、多文件上传与附件 Tag 展示/移除；主区为聊天与 Composer。
- **参考**：assistant-ui 仓库见 [assistant-ui/assistant-ui](https://github.com/assistant-ui/assistant-ui)。
