标准 Runtime 版：整体架构与模块边界

目标：FastAPI 作为独立 Agent Runtime 后端。前端未来只需要把它当成“智能执行服务”来调用。

↓ stateful orchestration

run_id, logs, timing, tool trace, error attribution

边界原则

Providers 只管模型调用，Agents 只管代理执行，Runtime 只管对外运行协议。三层各司其职，避免“一个 adapter 干完整个宇宙”。

为什么要拆

你当前项目的 `deep_agent_adapter` 已经同时承担了模型构造、agent 创建、流式解析、线程状态语义，后面一旦加技能治理和多运行模式，就很容易变成“上帝类”。

未来扩展

前端以后不需要理解 DeepAgents 或 LangGraph，只要理解 “发起一次 run / 订阅一次 run / 查看一次 session” 即可，后续换模型或换 agent 实现都不伤前端。
